# Подготовка к релизу

Что стоит сделать до того, как выложить проект людям, и как раздавать мобильное приложение без магазинов.

---

## Часть 1. Как раздавать приложение

### Почему не App Store и не Google Play

Обе площадки запрещают приложения, которые скачивают музыку с YouTube:

- **Apple**, правило 5.2.3 — про использование чужого контента без прав;
- **Google Play** — политика про обход ограничений сторонних сервисов.

Это не техническая преграда, а политика. Шансы пройти проверку близки к нулю, а на попытку уйдут деньги ($99 в год у Apple, $25 разово у Google) и недели ожидания. Проекты вроде Jellyfin, NewPipe и Navidrome живут вне магазинов — и это нормально.

### Что делать вместо этого

| Способ | Кому подходит | Что нужно от вас | Трение для пользователя |
|---|---|---|---|
| **Веб-приложение (PWA)** | Всем, и iPhone, и Android | Ничего — уже работает | Открыть адрес, добавить на экран |
| **APK файлом** | Android | Собрать и приложить к релизу | Разрешить установку из неизвестных источников |
| **F-Droid** | Android, идейные пользователи | Подать заявку, открытый код | Ничего, привычный магазин |
| **TestFlight** | iPhone, до 10 000 человек | $99 в год, проверка Apple | Поставить TestFlight |
| **Сборка в Xcode** | iPhone, технари | Ничего | Нужен Mac и Xcode |

### Что советую для первого релиза

**Основной путь — веб-приложение.** Оно уже собрано и раздаётся сервером, работает везде и обновляется само вместе с сервером.

**APK для Android** в GitHub Releases — там веб-версия проигрывает: нет фоновой загрузки и полноценного офлайна.

**Про iPhone нужно сказать прямо.** Сохранение треков в память телефона — главная причина ставить это приложение — в веб-версии на iOS практически не работает: Safari не даёт надёжно хранить большие файлы, хранилище может быть очищено системой, фоновой загрузки нет. Нативное приложение это умеет (проверено: сервер выключен, трек играет из памяти телефона).

Отсюда честная позиция для релиза:

| Кому | Что предложить | Офлайн |
|---|---|---|
| Android | APK | Полноценный |
| iPhone, офлайн не нужен | Веб-версия | Нет |
| iPhone, офлайн нужен | Сборка в Xcode или TestFlight | Полноценный |

Не пишите в README «работает офлайн на всех устройствах» — на iPhone через Safari это будет неправдой, и первый же пользователь это обнаружит в самолёте.

### Что честно сказать про ограничения веб-версии

Стоит написать это в README, чтобы люди не удивлялись:

- на iPhone браузер может выгрузить вкладку и остановить музыку при долгой работе в фоне;
- объём хранилища для офлайна на iOS ограничен, и система может его очистить при нехватке места;
- фоновая загрузка недоступна — приложение должно быть открыто.

Всё это на Android в APK работает лучше — отсюда и смысл второго способа.

## Часть 2. Чек-лист перед публикацией

### Безопасность — обязательно

- [ ] **Смените `APP_API_KEYS`.** В `.env.example` лежит `change-me-local-dev-key`; если оставить, любой, кто знает это значение, получит доступ к API.
- [ ] **Проверьте, что `.env` не попал в git:** `git check-ignore .env` должен вернуть путь. Если файл уже закоммичен — [почистите историю](https://docs.github.com/en/authentication/keeping-your-account-and-data-secure/removing-sensitive-data-from-a-repository) и смените ключи.
- [ ] **Не публикуйте `data/`** — там аккаунты, хеши паролей и ваша музыка.
- [ ] Если сервер смотрит в интернет — включите **HTTPS** и **Secure-флаг у cookie** (Настройки → Настройки сервера).

Быстрая проверка, что лишнее не уедет в репозиторий:

```bash
git status --porcelain --ignored | grep -E '^!!' | head
git ls-files | grep -E '\.env$|^data/' && echo "ВНИМАНИЕ: секреты в git" || echo "чисто"
```

### Юридическая часть — обязательно

- [ ] **Дисклеймер в README.** Он уже есть: инструмент для личного использования, ответственность на пользователе. Не убирайте.
- [ ] **Не раздавайте `yt-dlp` и `ffmpeg` в комплекте** — пусть пользователь ставит их сам. Так вы не распространяете инструменты обхода, а лишь поддерживаете их.
- [ ] **Оставьте внешние источники выключенными по умолчанию.** Сейчас так и есть: включение — осознанное действие пользователя. Это важная граница.

### Качество кода

- [ ] Тесты проходят:

```bash
go test ./... && \
(cd mobile && flutter analyze && flutter test) && \
(cd frontend/frontend && npx tsc -b && npm run build)
```

- [ ] Настроен CI, который гоняет это на каждый push (заготовка ниже).
- [ ] В репозитории нет мусора: временных скриншотов, логов, папок сборки.

### Документация

- [ ] README объясняет, **что это и зачем**, а не только как собрать.
- [ ] Написано, как поставить на телефон.
- [ ] Описано, что делать, когда не работает.
- [ ] Есть `LICENSE` (сейчас MIT), `SECURITY.md`, `CONTRIBUTING.md`.

### Удобство для новых людей

- [ ] Скриншоты в README — люди решают за пять секунд, стоит ли разбираться.
- [ ] Заполните «About» и темы репозитория на GitHub: `self-hosted`, `music`, `flutter`, `golang`.
- [ ] Включите Issues и добавьте шаблон для багрепорта.

## Часть 3. Что настроить в репозитории

### Автосборка

`.github/workflows/ci.yml`:

```yaml
name: CI
on: [push, pull_request]

jobs:
  server:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-go@v5
        with: { go-version: '1.22' }
      - run: go vet ./...
      - run: go test ./...

  mobile:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: subosito/flutter-action@v2
        with: { channel: stable }
      - run: cd mobile && flutter pub get && flutter analyze && flutter test

  web:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with: { node-version: '20' }
      - run: cd frontend/frontend && npm ci && npx tsc -b && npm run build
```

### Сборка релизов

Чтобы при теге автоматически собирались бинарники и APK — `.github/workflows/release.yml`:

```yaml
name: Release
on:
  push:
    tags: ['v*']

jobs:
  build:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-go@v5
        with: { go-version: '1.22' }
      - uses: subosito/flutter-action@v2
        with: { channel: stable }

      - name: Веб-клиент
        run: cd mobile && flutter pub get && flutter build web --release

      - name: Android APK
        run: cd mobile && flutter build apk --release

      - name: Бинарники сервера
        run: |
          GOOS=linux  GOARCH=amd64 go build -o dist/music-orchestrator-linux-amd64 .
          GOOS=linux  GOARCH=arm64 go build -o dist/music-orchestrator-linux-arm64 .
          GOOS=darwin GOARCH=arm64 go build -o dist/music-orchestrator-macos-arm64 .

      - uses: softprops/action-gh-release@v2
        with:
          files: |
            dist/*
            mobile/build/app/outputs/flutter-apk/app-release.apk
```

`linux-arm64` — это Raspberry Pi, самая частая площадка для домашнего сервера.

### Версии

Обычный [SemVer](https://semver.org/lang/ru/): `v0.1.0` для первого MVP. До `v1.0.0` вы вправе ломать совместимость — это ожидаемо и нормально.

Ведите `CHANGELOG.md`: людям нужно понимать, что изменилось, прежде чем обновлять сервер, на котором лежит их музыка.

## Часть 4. Что доделать до релиза

Честный список того, чего сейчас не хватает. Не всё блокирует запуск, но знать стоит.

**Желательно до релиза**

- **Массовая загрузка плейлиста.** Сейчас треки сохраняются на устройство по одному. «Скачать весь плейлист, пока я дома» — главный сценарий офлайна, и его нет.
- **Удаление с устройства.** Файлы можно только накапливать: место занимается, а кнопки «убрать» во вкладке «На устройстве» нет.
- **Скриншоты в README.**

**Можно после**

- Фоновая загрузка: сейчас приложение должно оставаться открытым.
- Двухфакторная аутентификация в мобильном приложении (на сервере поддержка есть).
- Ограничение частоты запросов к логину — защита от перебора паролей.
- Переезд с JSON-файла на SQLite, когда коллекция вырастет до тысяч треков.

Подробнее — в [roadmap.ru.md](roadmap.ru.md).

## Часть 5. Как рассказать о проекте

Если хотите, чтобы им пользовались не только вы:

- **r/selfhosted** на Reddit — ровно та аудитория;
- **Hacker News** (Show HN) — заходит, если объяснить, чем отличаетесь;
- **Awesome Self-Hosted** — список, куда стоит попасть;
- русскоязычные сообщества про домашние серверы.

Что писать: не «ещё один музыкальный плеер», а конкретную мысль — **музыка, которую вы скачали, остаётся у вас файлом, и её нельзя отобрать**. Это и есть отличие от стримингов.

И сразу честно про ограничения: нужен свой сервер, нужен `yt-dlp`, ответственность за скачанное на пользователе. Люди в этих сообществах ценят прямоту и мгновенно считывают приукрашивание.
