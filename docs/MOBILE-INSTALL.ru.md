# Установка на телефон

Как поставить приложение на свой iPhone или Android без магазинов. Без обещаний: что проверено — помечено, что не проверено — тоже.

---

## Сначала главное про iPhone

Ставится **только через Xcode на Mac**. Обхода нет: Apple не разрешает установку iOS-приложений иначе, и никакой инструмент этого не меняет.

И сразу про ограничение, которое обычно узнают слишком поздно:

| Аккаунт | Сколько живёт приложение | Цена |
|---|---|---|
| Обычный Apple ID | **7 дней**, потом перестаёт запускаться и надо переустановить | бесплатно |
| Apple Developer Program | 1 год, плюс раздача через TestFlight | $99 в год |

С бесплатным аккаунтом приложение придётся переставлять раз в неделю. Это ограничение Apple, а не проекта.

Если возиться с этим не хочется — откройте адрес сервера в Safari и добавьте на экран «Домой». Иконка и полноэкранный режим работают, но **сохранение треков в память телефона там не работает**: Safari не даёт надёжно хранить большие файлы. Офлайн есть только в нативной сборке.

## iPhone: пошагово

Нужен Mac, [Xcode](https://apps.apple.com/app/xcode/id497799835) и [Flutter](https://docs.flutter.dev/get-started/install/macos).

### 1. Подготовьте проект

```bash
cd mobile
flutter pub get
open ios/Runner.xcworkspace
```

Открывать нужно именно `.xcworkspace`, а не `.xcodeproj` — иначе Xcode не увидит зависимости.

### 2. Задайте свой Bundle Identifier

**Это обязательный шаг, без него сборка упадёт.** В Xcode: слева выберите **Runner** → вкладка **Signing & Capabilities**.

Поменяйте **Bundle Identifier** на свой, например `com.вашафамилия.orchestrator`.

Причина: в репозитории лежит `com.musicorchestrator.musicOrchestrator`, и Apple не даст двум разным разработчикам подписать один и тот же идентификатор. Пока не поменяете — будет ошибка про недоступный bundle id.

### 3. Подпишите

Там же:

- **Automatically manage signing** — включить.
- **Team** — выберите свой Apple ID. Если списка нет: Xcode → Settings → Accounts → «+» → Apple ID.

### 4. Поставьте на телефон

1. Подключите iPhone кабелем, разблокируйте, на вопрос «Доверять компьютеру?» ответьте «Доверять».
2. В Xcode сверху выберите ваш телефон вместо симулятора.
3. Нажмите ▶ (или `Cmd+R`).

Первый запуск закончится ошибкой про недоверенного разработчика. Это нормально: на телефоне откройте **Настройки → Основные → VPN и управление устройством**, найдите свой Apple ID и нажмите «Доверять». После этого приложение запустится.

### 5. Разрешения при первом старте

Приложение спросит доступ к локальной сети — **разрешите**. Без этого оно не увидит ваш сервер в домашней Wi-Fi сети и будет показывать «Нет связи с сервером».

Если случайно отказали: **Настройки → Music Orchestrator → Локальная сеть**.

## Android

**Честно: собрать APK на машине, где писалась эта инструкция, не удалось — там не установлен Android SDK.** Шаги ниже стандартные для Flutter и должны работать, но именно этот проект под Android не проверялся. Если что-то не сойдётся — напишите в issues, поправлю.

### Сборка

Нужен [Android Studio](https://developer.android.com/studio) (он поставит SDK) и Flutter.

```bash
cd mobile
flutter build apk --release
```

Готовый файл: `mobile/build/app/outputs/flutter-apk/app-release.apk`

### Установка

Перекиньте APK на телефон любым способом и откройте. Android спросит разрешение на установку из этого источника — разрешите.

Через кабель:

```bash
flutter install --release
```

### Важно про подпись

Сейчас релизная сборка подписана **отладочным ключом** (`signingConfig = signingConfigs.getByName("debug")` в `android/app/build.gradle.kts`).

Что это значит на практике:

- для себя — работает нормально;
- **раздавать людям в таком виде нельзя**: отладочный ключ одинаковый у всех и не защищает ничего;
- обновиться поверх чужой сборки не получится — Android откажется менять ключ подписи.

Перед публикацией релизов нужно создать свой keystore:

```bash
keytool -genkey -v -keystore ~/orchestrator-release.jks \
  -keyalg RSA -keysize 2048 -validity 10000 -alias orchestrator
```

и прописать его в `android/key.properties` (файл не должен попасть в git). Пока этого нет, считайте сборку личной.

## Настройка после установки

При первом запуске приложение спросит адрес сервера. Введите его вместе с портом:

```
http://192.168.1.50:18080
```

Узнать адрес компьютера с сервером:

```bash
ipconfig getifaddr en0          # macOS
hostname -I | awk '{print $1}'  # Linux
```

Сервер должен слушать не только сам себя. В `.env`:

```env
APP_ADDR=:18080
APP_CORS_ORIGINS=*
```

`APP_ADDR=127.0.0.1:18080` означает «только этот компьютер» — телефон не подключится.

### Чтобы работало вне дома

Дома телефон и сервер в одной сети, а на улице — нет. Самое простое решение — [Tailscale](https://tailscale.com): приватная сеть между вашими устройствами, без проброса портов.

```bash
curl -fsSL https://tailscale.com/install.sh | sh
sudo tailscale up
```

Поставьте Tailscale на телефон, войдите тем же аккаунтом — и сервер будет доступен по постоянному адресу откуда угодно.

## Что проверялось, а что нет

Чтобы не было сюрпризов:

| Что | Статус |
|---|---|
| Сборка и запуск на iOS-симуляторе | Проверено |
| Сборка под физический iPhone (компиляция) | Проверено |
| Установка на реальный iPhone кабелем | **Не проверялось** — не было устройства |
| Разрешение на локальную сеть в Info.plist | Добавлено, на устройстве не проверялось |
| Фоновое воспроизведение | Режим `audio` включён, на устройстве не проверялось |
| Сборка APK | **Не проверялось** — нет Android SDK |
| Веб-версия на iPhone через Safari | Проверено |

## Если не работает

**«Нет связи с сервером» на телефоне**

Проверьте по порядку:

1. Телефон и сервер в одной сети.
2. С телефона открывается `http://АДРЕС:18080/health` в браузере.
3. `APP_ADDR` начинается с `:`, а не с `127.0.0.1`.
4. На iPhone разрешён доступ к локальной сети.
5. Файрвол на сервере пропускает порт.

**Xcode ругается на bundle identifier**

Не поменяли его на свой — вернитесь к шагу 2.

**Приложение перестало запускаться через неделю**

Истёк бесплатный сертификат. Подключите телефон и запустите из Xcode заново.

**Звук замолкает при сворачивании**

Должно работать: фоновый режим включён. Если нет — проверьте, что установлена свежая сборка, а не старая с телефона.
